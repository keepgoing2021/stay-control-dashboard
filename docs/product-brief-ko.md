# 숙박 운영 대시보드 제품 기획 초안

## 한 줄 정의

중소형 호스텔 운영자가 객실 예약, 예약채널, 날짜별 가격 추천을 한곳에서 보고
사람이 승인한 뒤 가격을 반영할 수 있게 돕는 숙박 운영 대시보드.

## 핵심 고객

- 중소형 호스텔 운영자
- 객실 수 최대 100개까지의 숙소
- 여러 예약채널을 함께 쓰고, 가격 조정과 예약 관리를 수동으로 처리하는 운영자

## 초기 제품 원칙

1. 모든 주요 화면과 기능명은 한글로 표현한다.
2. 첫 버전은 실제 예약채널 연동 없이 더미 데이터 기반 대시보드로 만든다.
3. 가격은 자동 변경하지 않는다. 추천 가격을 보여주고 운영자가 승인한다.
4. 자동 변경 기능은 나중 단계로 미루되, 그 시점에는 알림과 승인 이력을 반드시 둔다.
5. 최대 100개 객실 운영에 맞춰 화면 밀도와 필터 구조를 설계한다.

## 첫 버전 범위

### 오늘의 운영

- 관리자가 출근 직후 처리할 순서를 먼저 보여준다.
- 입실 준비, 퇴실·청소, 객실 점검, 가격 승인, 채널 점검을 업무 흐름으로 분리한다.
- 각 업무 카드 안에서 예약자명, 객실, 예약채널, 금액 변동을 바로 확인할 수 있게 한다.
- 점유율, 오늘 매출, 청소·점검 작업, 채널 문제는 보조 지표로 낮춘다.
- 오늘 도착/출발 손님은 OTA 배지와 함께 보여준다.
- 운영 유지보수 영역에서 청소·점검 작업 큐, 객실 상태 변경, 채널 건강상태, 완료 기록을 한 번에 처리한다.
- 2차 운영 관리에서 반복 점검 체크리스트, 객실 문제 이력, 소모품·린넨 재고, 담당자별 작업 현황, 사진 증빙 더미 흐름을 보여준다.
- 3차 운영 인사이트에서 고장 반복 감지, 청소 지연 예측, 판매 중지 손실, 자동 알림, 월간 운영 리포트를 더미 신호 기반으로 보여준다.

### 오늘의 운영 설계 원칙

오늘의 운영 화면은 숫자 보고서가 아니라 업무 큐여야 한다. 관리자가 가장 먼저
궁금해하는 것은 매출 그래프가 아니라 "지금 무엇을 처리해야 하는가"이다.

- 1순위: 오늘 입실할 손님과 예약채널
- 2순위: 오늘 퇴실할 객실과 청소·점검 작업
- 3순위: 객실 판매 가능 여부와 완료 기록
- 4순위: 승인해야 하는 가격 추천
- 5순위: 동기화나 연결 문제가 있는 예약채널

숫자 카드는 크게 나열하지 않는다. 핵심 숫자는 업무 카드의 제목과 보조 지표로
넣고, 실제 처리 대상이 보이는 리스트를 우선한다.

### 객실·예약 관리

- 월간/주간 예약 캘린더
- 객실별 예약 상태
- 예약채널별 예약 표시
- 체크인/체크아웃 날짜
- 예약자명, 객실명, 숙박일수, 예약 금액
- 객실 막기/예약 수정은 첫 버전에서는 시뮬레이션으로 처리

예약 캘린더는 월 달력형보다 객실 재고형 타임라인을 우선한다.

- 왼쪽 고정 영역: 객실 타입, 객실 번호, 객실 상태 아이콘
- 오른쪽 스크롤 영역: 날짜별 예약 막대
- 객실 타입별 그룹: 스탠다드, 디럭스, 패밀리룸 등
- 현재 날짜/현재 시간 기준선
- 오늘 버튼, 이전/다음 기간 이동
- 시간별/일별 보기 전환
- 필터와 잠금 아이콘
- 예약 막대 안에 예약자명 표시
- 긴 예약은 여러 날짜에 걸쳐 이어지는 막대로 표시
- 짧은 예약은 잘리지 않도록 말줄임과 툴팁을 제공
- 하단에는 날짜별 판매 가능 객실 수를 고정 표시

### 예약채널 관리

- 에어비앤비, 부킹닷컴, 아고다, 익스피디아, 야놀자, 여기어때, 네이버예약 등 인기 예약채널 표시
- 채널별 연결 상태 더미 표시
- 채널별 가격 배율 설정
- 채널별 매출 기여도
- 채널별 수수료율은 더미 데이터로 시작

### 가격 최적화

- 날짜별 추천 가격
- 현재 가격과 추천 가격 비교
- 추천 이유 표시
  - 주말 수요
  - 임박 공실
  - 높은 점유율
  - 낮은 점유율
  - 공휴일/이벤트
  - 시장 평균 대비 낮거나 높은 가격
- 승인 대기, 승인 완료, 보류 상태
- 가격 승인 후 더미 데이터에 반영

### 수익 분석

- 월별 매출 추이
- 객실 점유율 추이
- 평균 객실단가 추이
- 예약채널별 매출
- 객실 타입별 매출
- 가격 추천 적용 전후 예상 매출 차이

## 첫 버전에서 하지 않을 것

- 실제 예약채널 API 연동
- 실제 결제 처리
- 실제 문자/카카오 알림 발송
- 실제 예측 모델 학습과 자동 의사결정
- 실제 직원 앱 기반 하우스키핑 배정
- 실제 사진 업로드 저장소와 현장 알림
- 고객 메시지 자동응답
- 회계/세금 신고
- 완전 자동 가격 변경

## 중요한 미확정 사항

- 국내 예약채널 API 접근 가능 범위
- 각 예약채널의 실제 연동 심사와 계약 조건
- 경쟁 숙소 가격 데이터를 합법적이고 안정적으로 수집하는 방식
- 운영자가 원하는 알림 채널: 앱, 이메일, 카카오, 문자 중 무엇인지
- 가격 추천을 몇 일 앞까지 제공할지

## 제공된 레퍼런스에서 반영할 점

### 예약 타임라인 화면

제공된 예약 화면들은 객실 수가 많은 숙소에서 월 달력보다 타임라인형 화면이
실무에 더 맞다는 점을 보여준다. 첫 버전의 핵심 화면은 아래 구조를 따른다.

- 객실을 세로 행으로 나열한다.
- 날짜를 가로 열로 나열한다.
- 객실 타입별로 접고 펼칠 수 있는 그룹을 둔다.
- 예약은 날짜 범위를 차지하는 막대로 표시한다.
- 예약자명은 막대 안에 표시하되, 공간이 좁으면 말줄임 처리한다.
- 막대 색상은 예약채널 또는 예약 상태를 구분하는 데 사용한다.
- 왼쪽 객실 목록은 고정하고, 날짜 영역만 가로 스크롤한다.
- 하단의 판매 가능 객실 수는 날짜별 재고 판단에 중요하므로 고정 영역으로 둔다.

### 운영 지표 카드 화면

예약 현황 카드 레퍼런스는 숫자 중심의 단순한 정보 구조가 좋다. 첫 버전은
복잡한 그래프보다 오늘의 예약, 숙박일, 매출, 평균 객실단가를 빠르게 확인하게
만드는 데 집중한다.

### 주의할 점

- 레퍼런스를 그대로 복제하지 않는다.
- 우리 제품은 중소형 호스텔 운영자 기준으로 더 한글 친화적이고 설명적인 용어를 쓴다.
- 100개 객실까지 버틸 수 있도록 행 높이, 고정 컬럼, 필터, 검색을 처음부터 고려한다.
- 색상만으로 상태를 구분하지 않고 텍스트/아이콘을 함께 제공한다.

## 다음 개발 순서

1. 더미 데이터 모델을 먼저 만든다.
2. 주요 메뉴와 화면 구조를 잡는다.
3. 오늘의 운영 대시보드를 만든다.
4. 객실·예약 캘린더를 만든다.
5. 가격 최적화 추천/승인 흐름을 만든다.
6. 예약채널 관리 더미 화면을 만든다.
7. 수익 분석 화면을 만든다.
8. 모바일/태블릿에서 핵심 정보가 깨지지 않는지 확인한다.

## 첫 번째 검증 목표

실제 API 없이도 운영자가 아래 질문에 30초 안에 답할 수 있어야 한다.

- 오늘 몇 객실이 체크인/체크아웃하는가?
- 이번 달 객실 점유율과 예상 매출은 어느 정도인가?
- 어떤 날짜의 가격을 올리거나 내려야 하는가?
- 가격 추천 중 승인해야 할 항목은 몇 개인가?
- 어떤 예약채널이 매출에 가장 크게 기여하는가?
